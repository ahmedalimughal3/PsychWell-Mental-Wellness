01 · Overview

Executive summary

PsychWell is a privacy-first mental wellness companion designed around a simple promise: everyday reflection should not require an account or surrendering personal thoughts to a cloud database.

The product combines a calm, editorial interface with practical wellness tools. A person can record a mood, write a journal entry, complete a self-check, try a guided exercise, search for support in Karachi, or talk with Dr. Aria. The default experience is browser-only and stores personal data in localStorage.

Core product principle: the user remains in control. The app makes local storage visible, offers a complete clear-data action, and explains that real AI mode sends messages away from the device only after explicit consent.

Project objectives

  • Provide a low-friction, judgment-free place for daily mental wellness reflection.
  • Keep journal, mood, assessment, and chat history local by default.
  • Support both English and Urdu, including right-to-left Urdu layout.
  • Offer useful AI-assisted conversation without presenting it as diagnosis, therapy, or emergency care.
  • Make safety boundaries and crisis escalation visible for high-risk language.

02 · Product design

Audience and experience

Target users

People in Pakistan who want a private, lightweight way to notice moods, process thoughts, learn calming practices, or decide when professional support may be useful.

The app is not intended to replace a qualified mental-health professional or emergency service.

Design direction

A quiet, editorial visual system uses deep green, warm cream, soft sage, and coral accents. Large serif headings create emotional space while compact cards keep practical actions easy to scan.

04 · AI implementation

Dr. Aria conversation architecture

Dr. Aria has two clearly separated modes. Offline reflection is the default and keeps messages on-device. Real AI is an opt-in path with a consent explanation that tells the user their messages will leave the device.

Server-side safety controls

  • Message length is validated at the API boundary, with a 1–1200 character limit.
  • History is filtered to valid user/assistant turns and capped to the last 12 turns.
  • The system instruction tells the model to be warm and CBT-grounded without diagnosing, prescribing, or claiming emergency-care capability.
  • English and Urdu prompts are selected from the requested language.
  • Crisis language is detected before an upstream call and receives a human-support escalation message instead.
  • Provider credentials stay server-side; the browser sends the conversation to the app route, not a provider key.

Provider activation status

Integrated but not activated in this environment: the real-AI API route and consent UX are present. Replit-managed OpenAI provisioning requested an account upgrade, and no personal OpenAI API key was provided. Therefore the report does not claim a live upstream completion; offline reflection remains the safe working default.

Privacy boundary

By default, there is no account, database, analytics pipeline, camera flow, or microphone flow. The browser stores local state. If the user explicitly chooses real AI mode, the latest chat history and current message are sent to the app's server route for provider processing, while the local copy remains in the browser.

Clear-data behavior: the Settings page confirms the destructive action and removes PsychWell local storage keys. The user can return to onboarding after the wipe.

Known limitation and next activation step

Real AI conversations are implemented behind an explicit privacy choice, but the current workspace declined the managed AI account upgrade and did not provide an OpenAI secret. To activate the upstream mode, provision the managed OpenAI integration or add an OpenAI API key through Replit Secrets; no key should be pasted into chat or committed to the repository.

  • SPA rewrite routes are included so application paths load correctly.
